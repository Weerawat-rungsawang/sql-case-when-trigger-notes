CASE

CASE WHEN คือ “สมอง” ที่ตัดสินใจ

เป็น expression ที่คืนค่าเดียวในแต่ละแถว ใช้เขียนเงื่อนไขแบบ “ถ้า…แล้ว…ไม่งั้น…” ได้ใน SELECT, ORDER BY, UPDATE และภายใน Trigger

ตรวจเงื่อนไขจากบนลงล่าง และ หยุดที่เงื่อนไขแรกที่เป็นจริง — ลำดับจึงสำคัญมาก

TRG

Trigger คือ “มือ” ที่ลงมือทำ

เป็นชุดคำสั่งที่ฐานข้อมูลเรียกให้เองเมื่อมี INSERT, UPDATE หรือ DELETE เกิดขึ้นกับตาราง

ใช้บันทึกประวัติ ตรวจสอบข้อมูลก่อนบันทึก หรืออัปเดตข้อมูลที่เกี่ยวข้อง เช่น ลดสต็อกหลังขายสินค้า

01

ปูพื้นก่อนสอบ

พื้นฐาน SQL ที่ต้องแม่นก่อนเขียน CASE และ Trigger

สองหัวข้อนี้ไม่ได้แยกจาก SQL พื้นฐานเลย — ถ้าไม่แน่ใจว่า query ทำงานตามลำดับไหน หรือ NULL ทำงานอย่างไร โค้ด CASE และ Trigger ก็จะพลาดง่าย

1.1 คำสั่ง SQL พื้นฐาน และ Trigger เกี่ยวข้องอย่างไร

คำสั่งหน้าที่ตัวอย่างTrigger ที่เกี่ยวข้อง
SELECTอ่านข้อมูลSELECT * FROM students;ไม่ทำให้ Trigger ทำงาน
INSERTเพิ่มแถวใหม่INSERT INTO orders (...) VALUES (...);BEFORE INSERT / AFTER INSERT
UPDATEแก้ไขแถวUPDATE products SET stock_qty = 10;BEFORE UPDATE / AFTER UPDATE
DELETEลบแถวDELETE FROM orders WHERE order_id = 1001;BEFORE DELETE / AFTER DELETE
i
จำสั้น ๆ: Trigger ไม่ทำงานเมื่อเราแค่ SELECT — ต้องมี INSERT, UPDATE หรือ DELETE เท่านั้น

1.2 ลำดับการทำงานของ query ที่ต้องรู้

เวลาเขียน SQL เราเขียน SELECT ก่อน แต่ฐานข้อมูลประมวลผลตามลำดับนี้:

ผลที่ตามมา: alias ที่สร้างใน SELECT เช่น grade_result ใช้ใน ORDER BY ได้ แต่โดยทั่วไป ใช้ใน WHERE ไม่ได้ เพราะ WHERE ทำงานก่อน SELECT

NULL คือ “ไม่ทราบค่า”

  • NULL ไม่เท่ากับ 0 และไม่เท่ากับ ''
  • score = NULL ให้ผลเป็น unknown ไม่ใช่ true
  • ใช้ IS NULL หรือ IS NOT NULL ในการตรวจ
  • ถ้า CASE ไม่มี ELSE และไม่เข้าเงื่อนไขใดเลย ผลลัพธ์จะเป็น NULL

Aggregate ที่ใช้บ่อย

  • SUM() — ผลรวม
  • COUNT() — นับจำนวน
  • AVG() — ค่าเฉลี่ย
  • MIN() / MAX() — ค่าต่ำสุด / สูงสุด
  • ถ้าใช้ aggregate กับคอลัมน์อื่น ต้องมี GROUP BY

02

เครื่องมือที่ 1

CASE WHEN: เขียนเงื่อนไขให้ SQL ตัดสินใจ

CASE WHEN เปลี่ยน “เงื่อนไข” ให้กลายเป็น “ค่า” ที่เอาไปแสดง บันทึก หรือใช้เรียงลำดับได้ หลักเดียวที่ต้องจำคือ: ตรวจจากบนลงล่าง และหยุดทันทีเมื่อเจอเงื่อนไขแรกที่เป็นจริง

2.1 โครงสร้างและหลักการทำงาน

รูปแบบที่ใช้บ่อยที่สุดคือ searched CASE ซึ่งเขียนเงื่อนไขได้อิสระ ทั้ง >=, BETWEEN, IN, AND, OR และ IS NULL

SQLcase_syntax.sql
CASE
  WHEN condition_1 THEN result_1
  WHEN condition_2 THEN result_2
  ...
  ELSE result_default
END
ส่วนประกอบความหมายจำเป็นไหม
CASEเปิด expressionจำเป็น
WHEN conditionเงื่อนไขที่ต้องการตรวจต้องมีอย่างน้อย 1 เงื่อนไข
THEN resultค่าที่จะคืนเมื่อเงื่อนไขเป็นจริงจำเป็น
ELSE resultค่าเริ่มต้นเมื่อไม่เข้าเงื่อนไขใดเลยไม่บังคับ แต่ ควรใส่
ENDปิด expressionจำเป็นเสมอ

นอกจากนี้ยังมี simple CASE ซึ่งเปรียบเทียบความเท่ากันอย่างเดียว:

SQLsimple_case.sql
SELECT order_id, status,
       CASE status
         WHEN 'DONE'    THEN 'เสร็จสิ้น'
         WHEN 'WAITING' THEN 'รอดำเนินการ'
         WHEN 'URGENT'  THEN 'เร่งด่วน'
         ELSE 'อื่น ๆ'
       END AS status_text
FROM orders;

เลือกใช้แบบไหน: ถ้าเป็นการเทียบค่าแบบตรงตัวใช้ simple CASE ได้ แต่ถ้าต้องใช้ >=, BETWEEN, IN หรือหลายเงื่อนไขรวมกัน ต้องใช้ searched CASE

i
CASE เป็น expression ไม่ใช่คำสั่ง: มัน คืนค่า หนึ่งค่าในแต่ละแถว จึงเอาไปใส่ใน SELECT, ORDER BY, UPDATE ... SET, INSERT ... VALUES หรือภายใน Trigger ได้ แต่ตัวมันเองไม่เปลี่ยนข้อมูลจนกว่าจะเอาไปใช้กับ UPDATE / INSERT

↓ เท็จ
2
ตรวจ WHEN #2 ต่อไป

SQLwrong_order.sql
CASE
  WHEN score >= 50 THEN 'Pass'
  WHEN score >= 80 THEN 'Excellent'
  ELSE 'Fail'
END

score = 90 จะได้ Pass เพราะเงื่อนไข >= 50 เป็นจริงก่อน และ CASE หยุดตรงนั้น

SQLright_order.sql
CASE
  WHEN score >= 80 THEN 'Excellent'
  WHEN score >= 50 THEN 'Pass'
  ELSE 'Fail'
END

score = 90 จะได้ Excellent เพราะเงื่อนไขที่เฉพาะกว่าและสำคัญกว่าอยู่ก่อน

ตัวอย่าง 1: แปลงคะแนนเป็นเกรด

ใช้ CASE ใน SELECT เพื่อสร้างคอลัมน์ผลลัพธ์ใหม่ โดยไม่ต้องเพิ่มคอลัมน์จริงลงในตาราง

SQL02_grade.sql
SELECT
  student_id,
  student_name,
  score,
  CASE
    WHEN score >= 80 THEN 'A'
    WHEN score >= 70 THEN 'B'
    WHEN score >= 60 THEN 'C'
    WHEN score >= 50 THEN 'D'
    ELSE 'F'
  END AS grade_result
FROM students;

ตัวอย่าง 2: จัดระดับลูกค้าจากยอดซื้อสะสม

CASE ใช้กับค่าที่คำนวณจาก aggregate ได้ เช่น SUM(total_amount) โดยจัดกลุ่มด้วย GROUP BY customer_id

SQL03_customer_level.sql
SELECT
  customer_id,
  SUM(total_amount) AS total_spending,
  CASE
    WHEN SUM(total_amount) >= 50000 THEN 'VIP'
    WHEN SUM(total_amount) >= 10000 THEN 'Gold'
    ELSE 'Standard'
  END AS customer_level
FROM orders
GROUP BY customer_id;

กับดัก: ใช้ alias ใน CASE เดียวกัน

SQLalias_trap.sql
SELECT
  customer_id,

  CASE
    WHEN total_spending >= 50000 THEN 'VIP'
    ELSE 'Standard'
  END AS customer_level
FROM orders
GROUP BY customer_id;

ตัวอย่าง 3: เรียงลำดับความสำคัญด้วย CASE ใน ORDER BY

บางครั้งลำดับที่ธุรกิจต้องการไม่ใช่ A–Z หรือมากไปน้อย แต่เป็นลำดับที่กำหนดเอง เช่น ต้องการเห็น URGENT → WAITING → DONE

SQL04_priority_order.sql
SELECT order_id, status, total_amount, order_date
FROM orders
ORDER BY
  CASE
    WHEN status = 'URGENT'  THEN 1
    WHEN status = 'WAITING' THEN 2
    WHEN status = 'DONE'    THEN 3
    ELSE 4
  END,
  order_date DESC;

2.4 CASE กับ Aggregate: ทำรายงานแบบมีเงื่อนไข

Pattern ที่มีประโยชน์มากและมักออกสอบคือการใส่ CASE ไว้ใน SUM() หรือ COUNT() เพื่อนับ/รวมเฉพาะบางเงื่อนไข

SQL07_conditional_aggregate.sql
SELECT
  SUM(CASE WHEN status = 'DONE'    THEN total_amount ELSE 0 END) AS done_total,
  SUM(CASE WHEN status = 'WAITING' THEN total_amount ELSE 0 END) AS waiting_total,
  SUM(CASE WHEN status = 'URGENT'  THEN total_amount ELSE 0 END) AS urgent_total,
  COUNT(CASE WHEN status = 'URGENT' THEN 1 END) AS urgent_count
FROM orders;

ทำไม SUM ต้องมี ELSE 0

ถ้าไม่ใส่ ELSE ค่าที่ไม่เข้าเงื่อนไขจะเป็น NULL และ SUM จะข้าม NULL ไป ผลรวมอาจดูเหมือนเดิม แต่ถ้าทุกแถวไม่เข้าเงื่อนไขเลย SUM จะคืน NULL ไม่ใช่ 0 ซึ่งอาจทำให้รายงานผิด

ทำไม COUNT ไม่ต้องมี ELSE

COUNT(CASE WHEN ... THEN 1 END) จะนับเฉพาะค่าที่ไม่เป็น NULL — แถวที่ไม่เข้าเงื่อนไขได้ NULL และถูก COUNT ข้ามไป จึงนับเฉพาะที่ตรงเงื่อนไขได้พอดี

3.9 ใช้ CASE WHEN ภายใน Trigger

นี่คือจุดที่สองหัวข้อบรรจบกัน: หลังมี order ใหม่ ให้อัปเดตยอดซื้อสะสมของลูกค้า และจัดระดับใหม่ด้วย CASE WHEN

i
หลักสำคัญ: คำนวณยอดใหม่ลงตัวแปร v_new_total ก่อน แล้วใช้ตัวแปรนี้ทั้งในการบันทึกยอดและการจัดระดับ — ช่วยให้อ่านค่าเดิมครั้งเดียวและหลีกเลี่ยงปัญหาบวกซ้ำใน MySQL
SQL11_customer_level_trigger.sql
DELIMITER //

CREATE TRIGGER trg_orders_after_insert_level
AFTER INSERT ON orders
FOR EACH ROW
BEGIN
  DECLARE v_new_total DECIMAL(12,2);

  SELECT total_spending + NEW.total_amount
    INTO v_new_total
  FROM customers
  WHERE customer_id = NEW.customer_id;

  UPDATE customers
  SET total_spending = v_new_total,
      customer_level = CASE
        WHEN v_new_total >= 50000 THEN 'VIP'
        WHEN v_new_total >= 10000 THEN 'Gold'
        ELSE 'Standard'
      END
  WHERE customer_id = NEW.customer_id;
END//

DELIMITER ;

ลำดับการทำงาน

  1. มี INSERT order ใหม่
  2. Trigger ทำงานหลัง order ถูกบันทึก
  3. อ่านยอดเดิม + NEW.total_amount เก็บลง v_new_total
  4. ใช้ v_new_total จัดระดับด้วย CASE
  5. อัปเดตยอดและระดับเฉพาะลูกค้าคนนั้น

ทำไมต้องใช้ v_new_total

เพราะ customer_level ต้องสะท้อนยอด หลัง รวม order ใหม่ ไม่ใช่ยอดเก่า ถ้าใช้ total_spending เฉย ๆ ลูกค้าที่เพิ่งข้ามเกณฑ์อาจยังได้ระดับเดิม

3.13 Best Practices ในการเขียน Trigger

ควรทำ

  • ตั้งชื่อให้สื่อ: trg_<table>_<timing>_<event>
  • หนึ่ง Trigger หนึ่งหน้าที่ชัดเจน
  • Validate ด้วย BEFORE, Audit ด้วย AFTER
  • ใช้ SIGNAL พร้อมข้อความที่เข้าใจง่าย
  • ทดสอบด้วย SELECT ก่อน/หลังทุกครั้ง
  • เก็บ SQL สร้าง Trigger ไว้ใน version control
  • เขียน comment อธิบาย business rule

ไม่ควรทำ

  • ยัด business logic ทั้งระบบไว้ใน Trigger
  • เขียน Trigger ที่เรียกงานหนัก ๆ ต่อแถว
  • พึ่ง Trigger แทน foreign key หรือ constraint พื้นฐาน
  • ลืมว่า Trigger ทำงานซ้ำเมื่อ insert หลายแถว
  • สร้าง audit ซ้ำจากหลาย Trigger
  • ละเลย error handling และ rollback behavior
  • แก้ Trigger ใน production โดยไม่มี script
✓
Debug อย่างเป็นระบบ: 1) ดูว่า Trigger ถูกสร้างจริงด้วย SHOW TRIGGERS 2) ทดสอบ DML ทีละแถว 3) ตรวจ log table 4) ถ้า error ให้อ่านรหัส error และบรรทัดที่ชี้ 5) ลอง drop แล้วสร้างใหม่ในฐานข้อมูลทดสอบ

SELECT
  student_id,
  student_name,
  score,
  CASE
    WHEN score >= 80 THEN 'A'
    WHEN score >= 70 THEN 'B'
    WHEN score >= 60 THEN 'C'
    WHEN score >= 50 THEN 'D'
    ELSE 'F'

FROM students
ORDER BY student_id;

5.2 แบบฝึกหัด Trigger

01

บันทึกการเปลี่ยนแปลงสต็อก

สร้าง Trigger หลัง UPDATE ตาราง products เพื่อบันทึก product_id, old_stock, new_stock, action_name และ update_time ลง product_stock_log

เฉลย ดูโค้ดและผลทดสอบ
SQLlab_trigger_01.sql
DELIMITER //

CREATE TRIGGER trg_products_after_update
AFTER UPDATE ON products
FOR EACH ROW
BEGIN
  INSERT INTO product_stock_log
    (product_id, old_stock, new_stock, action_name, update_time)
  VALUES
    (NEW.product_id, OLD.stock_qty, NEW.stock_qty, 'UPDATE', NOW());
END//

DELIMITER ;

ทดสอบ:

SQLlab_trigger_01_test.sql
UPDATE products
SET stock_qty = stock_qty + 5
WHERE product_id = 3;

SELECT * FROM product_stock_log
ORDER BY log_id DESC;

ผลที่ควรได้: product 3, old_stock 7, new_stock 12, action UPDATE — ถ้าต้องการบันทึกเฉพาะเมื่อสต็อกเปลี่ยนจริง ให้เพิ่ม IF OLD.stock_qty <> NEW.stock_qty THEN ... END IF;

02

ห้ามจำนวนสินค้าติดลบหรือเป็นศูนย์

สร้าง Trigger ก่อน INSERT ตาราง order_items เพื่อห้าม quantity <= 0 พร้อมข้อความ error ที่ชัดเจน

เฉลย ดูโค้ดและผลทดสอบ
SQLlab_trigger_02.sql
DELIMITER //

CREATE TRIGGER trg_order_items_before_insert
BEFORE INSERT ON order_items
FOR EACH ROW
BEGIN
  IF NEW.quantity <= 0 THEN
    SIGNAL SQLSTATE '45000'
      SET MESSAGE_TEXT = 'Quantity must be more than 0';
  END IF;
END//

DELIMITER ;

ทดสอบ:

SQLlab_trigger_02_test.sql
INSERT INTO order_items(order_id, product_id, quantity, unit_price)
VALUES (1001, 2, 0, 390.00);

ผลที่ควรได้: ERROR 1644 (45000): Quantity must be more than 0 และไม่มีแถวใหม่ถูกบันทึก

03

ผลที่ควรได้: stock 3 → 2 และถ้ามี Trigger log จากข้อ 1 จะเกิด log old_stock 3, new_stock 2 เพิ่มอีกหนึ่งแถว

04

อัปเดตยอดลูกค้า + จัดระดับ + Audit

สร้าง Trigger หลัง INSERT ตาราง orders เพื่ออัปเดต total_spending, customer_level ด้วย CASE WHEN (VIP ≥ 50,000, Gold ≥ 10,000, otherwise Standard) และเพิ่มแถวลง order_audit

เฉลย ดูโค้ดและผลทดสอบ
SQLlab_trigger_04.sql
DELIMITER //

CREATE TRIGGER trg_orders_after_insert_full
AFTER INSERT ON orders
FOR EACH ROW
BEGIN
  DECLARE v_new_total DECIMAL(12,2);

  SELECT total_spending + NEW.total_amount
    INTO v_new_total
  FROM customers
  WHERE customer_id = NEW.customer_id;

  UPDATE customers
  SET total_spending = v_new_total,
      customer_level = CASE
        WHEN v_new_total >= 50000 THEN 'VIP'
        WHEN v_new_total >= 10000 THEN 'Gold'
        ELSE 'Standard'
      END
  WHERE customer_id = NEW.customer_id;

  INSERT INTO order_audit(order_id, action_name, action_time, note)
  VALUES (NEW.order_id, 'INSERT', NOW(),
          CONCAT('amount=', NEW.total_amount));
END//

DELIMITER ;

SQLlab_trigger_04_test.sql

FROM customers WHERE customer_id = 2;

FROM customers WHERE customer_id = 2;

ผลที่ควรได้: customer 2 จาก 48,000 Gold → 53,000 VIP และมี audit 1 แถว — ถ้ามี Trigger audit เดิมอยู่แล้ว อย่า INSERT audit ซ้ำในตัวนี้

Quiz: CASE WHEN & Trigger

01จากคำสั่งนี้ ถ้า score = 90 จะได้ผลลัพธ์อะไร?
CASE WHEN score >= 50 THEN 'Pass' WHEN score >= 80 THEN 'Excellent' ELSE 'Fail' END

เฉลย A: CASE ตรวจจากบนลงล่างและหยุดที่เงื่อนไขแรกที่เป็นจริง — 90 >= 50 เป็นจริงก่อน จึงได้ Pass และไม่ตรวจ >= 80 อีก

02ถ้า stock_qty = 15 คำสั่งนี้ให้ผลอะไร?
CASE WHEN stock_qty = 0 THEN 'Out' WHEN stock_qty BETWEEN 1 AND 10 THEN 'Low' END

เฉลย C: ไม่มี ELSE และไม่มีเงื่อนไขใดเป็นจริง (15 ไม่ใช่ 0 และไม่ถึง 10) จึงคืน NULL

03ใน AFTER INSERT ON orders ต้องการอ่านค่า order_id ของแถวใหม่ ต้องใช้ตัวใด?

เฉลย B: INSERT มีเฉพาะแถวใหม่ จึงใช้ NEW และใน AFTER INSERT ค่า AUTO_INCREMENT ถูกสร้างแล้ว

04ใน Trigger ที่ทำงานกับ DELETE มี row alias ใดใช้ได้?

เฉลย B: DELETE มีเพียงข้อมูลเดิมที่จะถูกลบ จึงใช้ OLD — ไม่มีแถวใหม่ให้ใช้ NEW

05ต้องการปฏิเสธ quantity <= 0 ควรใช้ Trigger แบบใด?

เฉลย B: Validation ต้องใช้ BEFORE เพื่อหยุดข้อมูลผิดก่อนถูกเขียนลงตาราง และสามารถแก้ไข NEW ได้ถ้าต้องการ

06ข้อใดถูกเกี่ยวกับ NEW?

เฉลย B: NEW เป็นตัวแทนแถวใหม่และสามารถกำหนดค่าได้ใน BEFORE trigger เช่น SET NEW.created_at = NOW(); แต่ AFTER trigger แก้ไม่ได้

07Trigger ของ MySQL ทำงานบ่อยแค่ไหน?

เฉลย C: MySQL ใช้ row-level trigger และต้องระบุ FOR EACH ROW — INSERT 100 แถวจะทำให้ Trigger ทำงาน 100 ครั้ง

08เพราะเหตุใดจึงต้องใช้ DELIMITER // เมื่อสร้าง Trigger?

เฉลย B: DELIMITER เป็นคำสั่งฝั่ง client ใช้เปลี่ยนตัวคั่นชั่วคราว เพื่อไม่ให้ client ตัดจบที่ ; ภายใน BEGIN ... END

09SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '...' มีหน้าที่อะไร?

เฉลย B: SIGNAL ใช้โยน error เอง — SQLSTATE 45000 เป็น user-defined exception และ client จะเห็นเป็น error 1644 พร้อมข้อความที่กำหนด

10เกิดอะไรขึ้นถ้า Trigger บน orders พยายาม UPDATE orders ใน AFTER INSERT?

เฉลย B: MySQL ไม่อนุญาตให้ Trigger แก้ตารางที่ statement กำลังใช้งานอยู่ — ต้องแก้ตารางอื่นแทน

11ต้องการเรียง order ให้ URGENT มาก่อน WAITING แล้วจึง DONE ควรใช้ข้อใด?

เฉลย B: ORDER BY status จะเรียงตามตัวอักษร (DONE, URGENT, WAITING) ซึ่งผิดกฎธุรกิจ ต้องใช้ CASE แปลงสถานะเป็นตัวเลขลำดับ

12ข้อใด ไม่ได้รับอนุญาต ภายใน Trigger ของ MySQL?

เฉลย C: Trigger ห้ามใช้คำสั่งควบคุม transaction เช่น START TRANSACTION, COMMIT, ROLLBACK — แต่ใช้ IF, SIGNAL และ UPDATE ตารางอื่นได้

6.2 ถาม–ตอบสั้น ทบทวนก่อนสอบ

ลองตอบในใจก่อนเปิดคำตอบ
CASE WHEN คืออะไร และใช้ที่ไหนได้บ้าง?

เป็น expression ที่ใช้เขียนเงื่อนไขแบบ “ถ้า…แล้ว…ไม่งั้น…” และคืนค่าเดียว ใช้ได้ใน SELECT, ORDER BY, UPDATE ... SET, INSERT ... VALUES และภายใน Trigger

CASE ตรวจเงื่อนไขอย่างไร?

ตรวจจากบนลงล่าง และหยุดที่เงื่อนไขแรกที่เป็นจริง — เงื่อนไขที่อยู่หลังจะไม่ถูกตรวจอีก ดังนั้นเงื่อนไขที่เฉพาะกว่าหรือสำคัญกว่าต้องอยู่ก่อน

ถ้า CASE ไม่มี ELSE และไม่มีเงื่อนไขใดเป็นจริง จะได้อะไร?

ได้ NULL — ไม่ใช่ 0 และไม่ใช่ข้อความว่าง

ทำไมเงื่อนไขช่วงคะแนนต้องเรียงจากมากไปน้อย?

เพราะถ้าเอาเงื่อนไขกว้าง เช่น >= 50 ไว้ก่อน คะแนน 90 จะ match เงื่อนไขนั้นทันทีและไม่ได้ตรวจ >= 80 อีก

CASE ใช้ใน ORDER BY อย่างไร?

ใช้แปลงสถานะเป็นตัวเลขลำดับ เช่น URGENT = 1, WAITING = 2, DONE = 3 แล้วเรียงด้วยตัวเลขนั้น จากนั้นใส่ตัวเรียงรองเช่น order_date DESC

CASE ใช้กับ aggregate ได้ไหม?

ได้ เช่น SUM(CASE WHEN status = 'DONE' THEN total_amount ELSE 0 END) หรือ COUNT(CASE WHEN status = 'URGENT' THEN 1 END) — เป็น pattern ทำรายงานแบบมีเงื่อนไข

Trigger คืออะไร?

ชุดคำสั่งที่ฐานข้อมูลเรียกให้เองเมื่อเกิด INSERT, UPDATE หรือ DELETE บนตาราง — ไม่ต้อง CALL เหมือน stored procedure

BEFORE กับ AFTER ต่างกันอย่างไร?

BEFORE ทำงานก่อนแถวถูกเขียน — เหมาะกับ validate และแก้ไข NEW; AFTER ทำงานหลังแถวถูกเขียน — เหมาะกับ audit, cascade และใช้ค่า AUTO_INCREMENT

NEW กับ OLD ใช้ต่างกันอย่างไร?

NEW = ข้อมูลแถวใหม่ ใช้กับ INSERT และ UPDATE; OLD = ข้อมูลแถวเดิม ใช้กับ UPDATE และ DELETE; OLD อ่านได้อย่างเดียว ส่วน NEW แก้ได้เฉพาะ BEFORE trigger

ทำไมต้องใช้ DELIMITER?

เพราะ body ของ Trigger มีเครื่องหมาย ; หลายตัว ถ้าไม่เปลี่ยน delimiter client จะตัดจบคำสั่งตั้งแต่ ; ตัวแรกภายใน BEGIN ... END

Trigger ตรวจสอบข้อมูลควรใช้ BEFORE หรือ AFTER?

BEFORE — เพื่อปฏิเสธข้อมูลผิดก่อนถูกเขียนลงตาราง และใช้ SIGNAL เพื่อยกเลิก statement

Trigger สามารถแก้ตารางที่ตัวเองผูกอยู่ได้ไหม?

ไม่ได้ — จะเกิด ERROR 1442 เพราะตารางถูกใช้โดย statement ที่เรียก Trigger อยู่ แต่แก้ตารางอื่นได้ เช่น Trigger บน orders อัปเดต customers

SIGNAL SQLSTATE '45000' คืออะไร?

การส่ง error ที่ผู้ใช้กำหนดเอง โดย 45000 เป็น unhandled user-defined exception และสามารถกำหนด MESSAGE_TEXT เป็นข้อความที่ต้องการให้ client เห็น

จะดู Trigger ที่มีอยู่ได้อย่างไร?

ใช้ SHOW TRIGGERS;, SHOW CREATE TRIGGER ชื่อ; หรือ query จาก information_schema.TRIGGERS

CASE WHEN ภายใน Trigger ใช้ทำอะไร?

ใช้จัดระดับหรืออัปเดตสถานะอัตโนมัติ เช่น คำนวณ customer_level จากยอดซื้อสะสมหลังมี order ใหม่
